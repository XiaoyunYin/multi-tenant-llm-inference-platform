# CPU-only M5 stage 1

Xiaoyun approved this local stage on 2026-10-02 (Claude REVIEW Round 43, DEC-030). It prepares the qualified claim "Kubernetes (kind, local, mock vLLM backends)" for Claude review. Full EKS/GPU M5 acceptance remains separate.

From the repository root, with Docker Linux containers, Go 1.26.6, Python 3.12.7 and uv 0.9.5:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/m5-stage1.ps1 -OutputDirectory experiments/inf037a/<new-run-id>
```

The single entrypoint calls `inference_platform.kind_rollout`. It verifies/downloads hash-pinned kind 0.30.0 and kubectl 1.34.0, builds three amd64 images locally with provenance indexes disabled, creates the digest-pinned Kubernetes 1.34.0 kind node, loads images with `kind load docker-image`, deploys, starts eight SSE workers, rolls both gateway replicas, replaces only backend ordinal 1, reconciles outcomes/reservations, exports allowlisted evidence and checksums, deletes the cluster, and verifies no cluster containers remain. It refuses an existing cluster of the same name or an existing evidence directory. Loopback port 18080 must be free. Downloads fetch public tools/base images/tokenizer files; no images are pushed and no AWS API or Terraform command is invoked. Linux amd64 can run the same module via `uv run --project python --locked python -m inference_platform.kind_rollout --output experiments/inf037a/<new-run-id>`.

`resources.yaml` specifies two gateway replicas, single disposable Redis, two stable StatefulSet backend slots, a headless backend Service, namespace-scoped list-only EndpointSlice RBAC, startup/readiness probes, PDBs and graceful termination. The script makes `local-config` from the versioned tenant and predictable local-only salt example; these are development inputs, not production secrets. Gateway access uses NodePort on loopback; backend requests always use the selected pod IP. All application pods use `imagePullPolicy: Never`. Redis persistence is disabled; restart/HA durability is outside this measurement.

The gateway rollout uses maxSurge=1/maxUnavailable=0 and can temporarily run three gateways; the desired replica count remains two. Backend partition=1 replaces only fake-1 with no surge; fake-0 retains its UID. PDBs protect voluntary eviction; they do not constrain controller-driven rollouts, whose strategies supply the capacity bounds. The preStop sleep is three seconds. The gateway total request bound is 120s, drain grace 125s, hard stop 10s and pod grace 150s, leaving 12s for release/exit after preStop and the full shutdown bounds. The fake wrapper drains for at most 130s. R090's follow-up uses 24 chunks at 1250ms (~30s) with worker starts staggered by 0.4s; all eight workers must be live before mutation. This supplies margin beyond preStop plus the serial gateway rollout step, while staying well inside the 120s ceiling. Every terminated gateway/backend must have nonzero live-stream coverage at SIGTERM or the campaign fails, even if every stream completed.

Discovery is disabled by default. Opt in with `BACKEND_DISCOVERY=endpointslices`, `BACKEND_DISCOVERY_NAMESPACE` and `BACKEND_DISCOVERY_SERVICE`; `BACKEND_DISCOVERY_INTERVAL` defaults to 250ms. Only named `http` TCP ports, ready nonterminating Pod endpoints and direct valid pod IPs are admitted. Pod names supply stable identity; UIDs supply generation. Unknown readiness is excluded. List/auth/timeout/invalid-payload errors clear the membership snapshot; successful discovery plus independent backend health is required to recover. In-flight requests retain their chosen backend; there is no service load-balancing hop or retry to another backend. API observation delay is bounded by the poll cadence plus a one-second API timeout, rather than an instantaneous removal guarantee. Generation changes discard health and load samples. `--check-config` remains offline for both modes; default static `BACKENDS` validation is preserved.

Evidence includes every client's terminal status and duration, gateway routing/terminal/drain records, sampled Pod readiness and EndpointSlice conditions, per-stage wall timestamps with removal observation brackets, live requests at mutation, Redis global and tenant reservation cardinalities plus active reservation keys, image/source hashes, and verified teardown. Per terminated generation it records streams in flight at the first observed deleting snapshot and at SIGTERM, plus each covered stream's post-signal time to its gateway terminal record. Deletion has a last-nondeleting/first-deleting observation bracket; it is not inferred from the API's future deletion deadline ([ObjectMeta semantics](https://kubernetes.io/docs/reference/kubernetes-api/definitions/object-meta-v1-meta/)). Backend intervals are gateway-observed and its own SIGTERM active counter must also be nonzero; the separate native drain acknowledgment supplies the backend drain timing. Generation IDs are hashed consistently; tokens, salts, prompts, IPs, raw kubeconfig/API responses and reservation IDs are excluded. Distributions report sample count, minimum, empirical median, mean and maximum; p95 is unavailable below 400 samples under PLAN's tail-sample rule. No population-tail or GPU-performance inference is supported. Read the run analysis as well as the summary counts.

Pins and API semantics are grounded in the [kind 0.30.0 release](https://github.com/kubernetes-sigs/kind/releases/tag/v0.30.0), [EndpointSlice documentation](https://kubernetes.io/docs/concepts/services-networking/endpoint-slices/) and [pod termination flow](https://kubernetes.io/docs/concepts/workloads/pods/pod-lifecycle/#pod-termination-flow).

Any future PlanPaid must re-pin the Stage C payloads because gateway sources changed. This stage does not refresh or authorize those historical payloads.
